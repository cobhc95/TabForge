# Debugging by symptom

Start here when you know what went wrong for the user but not where it lives. Each row gives the first file or folder to read and the first test, command or log to run. Command syntax and the full command list are in `Source/docs/guides/DEBUGGING.md`. Use `--profile <scratch folder>` for every run, and `--only <TestName>` (see the test registry for the names).

With `--profile <folder>`, the settings, the diagnostics folder and the recovery folder move under that folder. The engine log stays in `%TEMP%` either way, so check it for every run.

The `TABFORGE_TRACE` areas are opt-in and cost nothing when unset. `errors.log` is the first place to look for a silent failure: every swallowed error in a `catch` that goes through `Trace.Error` is written there. Render and pointer-move paths write nothing to it.

## Choosing the first step

1. Reproduce with the smallest song that shows the symptom, through the headless command in the table when one exists. A command that exits 1 names the problem.
2. Read `errors.log` and the engine log from the same run before touching code.
3. Turn on one `TABFORGE_TRACE` area, not all of them, so the trace stays small.
4. Run the first `--only` test that matches the symptom. If none exists, add one before fixing.
| `Run-DataAB` reports "step failed in OLD: … save-copy exit timeout" and "settings-roundtrip exit timeout", with the OLD files missing, while the NEW build passes (data A/B baseline too old) | The OLD build predates the `--save-copy` and settings round-trip commands (added with the data A/B run), so it starts normally and waits until the step times out. | Publish a baseline built from a commit that has the `--save-copy` command (for a phase gate, the commit at the end of the previous phase) and pass it as `-Old`. |
| `TabForge.exe --selftest <log> ...` exits at once with no log file while `--only` runs from the same build work (self-test run left no log) | Another TabForge process was running (a render-identity run, a basic run or the app); the single-instance service hands the new start to it and exits. | Run the self-test when no other TabForge process is running (check Task Manager or `Get-Process TabForge`), or wait for the other run to finish. |
