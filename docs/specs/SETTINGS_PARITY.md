# Settings entry-point parity

A setting that can be changed from more than one place must end in the same state from each: the open tabs, the stored value, the menu check mark. `TestSettingsEntryPointParity` (former settings-parity suite, removed in Batch 2 ([canonical note](../guides/TESTING.md#removed-in-batch-2-canonical-note)); area `settings`) changes each listed setting through Preferences (the live-preview path, which is also the Apply path) and through its other entry point on a window with two tabs, and compares the observed state. Preferences is modal, so another entry point cannot change a row while it is open; Cancel restores the old values through the same applier.

The rule: every entry point calls one window setter; each settings applier (subscribed to `MainWindowSettings.SettingsChanged` in `MainWindow.Compose.cs`, e.g. `ScoreSettingsApplier`) calls that same setter when the value changed since its last apply.
