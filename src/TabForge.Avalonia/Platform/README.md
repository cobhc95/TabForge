# TabForge.Avalonia platform adapters

- Owns: the Avalonia adapters of the Core ports and the drawing hosts that take a raw `DrawingContext` (the port-readiness budget allows them only here).
- Does not own: feature logic (Core presenters) or window layout (`Source/src/TabForge.Avalonia/Views`).
- Tests: the headless test project (`dotnet test`).

| File | Owns |
|---|---|
| `Source/src/TabForge.Avalonia/Platform/AvaloniaUiThread.cs` | `IUiThread` over the Avalonia dispatcher; each call maps one to one with the same priority. |
| `Source/src/TabForge.Avalonia/Platform/AvaloniaScoreClipboard.cs` | `IScoreClipboard` over the Avalonia clipboard: the same private format bytes and text as the WPF app; fetched before each paste. |
| `Source/src/TabForge.Avalonia/Platform/AvaloniaUiTimer.cs` | `IUiTimer` over an Avalonia dispatcher timer (made by `AvaloniaUiThread.CreateTimer`). |
| `Source/src/TabForge.Avalonia/Platform/AvaloniaDrawContext.cs` | `IDrawContext` over an Avalonia drawing context, with cached brushes, pens and typefaces as in the WPF adapter. `pixelsPerDip` is unused (Avalonia scales text with the render target). |
| `Source/src/TabForge.Avalonia/Platform/AvaloniaPathsAndText.cs` | `IPathFactory` and `ITextMeasure`, the twin of the WPF adapter. |
| `Source/src/TabForge.Avalonia/Platform/AvaloniaPalette.cs` | Every Core palette key as a brush, in a dark and a light theme dictionary. |
| `Source/src/TabForge.Avalonia/Platform/HoverSurfaces.cs` | The stronger Avalonia hover and press surfaces: shades that clear 1.6:1 against the window, the panel and the Panel2 cards (and keep the primary text above 4.5:1), where the Core HoverBrush only guards 1.3:1; the Core values and the WPF output are unchanged. |
| `Source/src/TabForge.Avalonia/Platform/AvaloniaLooks.cs` | Each Core look rule as an Avalonia style (look name as the selector class; conditions as pseudo classes; template-part setters as `Kind.Look:state /template/ Border#part`). |
| `Source/src/TabForge.Avalonia/Platform/AvaloniaCheckSliderStyles.cs` | The WPF-style CheckBox (15 DIP box, accent tick, class of the Core "CheckBox" look) and default Slider templates for every such control. |
| `Source/src/TabForge.Avalonia/Platform/AvaloniaArrangementSlider.cs` | The compact blue mixer slider template (class ArrangementSlider) with the value-printing thumb of the Core "ArrangementSliderThumb" look. |
| `Source/src/TabForge.Avalonia/Platform/AvaloniaButtonTemplates.cs` | The Button and ToggleButton look templates: nested borders named after the WPF template parts the look uses (for example b, Bd, Chrome) around the content presenter. |
| `Source/src/TabForge.Avalonia/Platform/AvaloniaDialogHost.cs` | Modal show over an owner, with the `Capture` seam (the dialog goes to the hook, which returns its result) that matches the WPF `DialogHost.Capture`. Esc and Enter are the dialog's cancel and default buttons. |
| `Source/src/TabForge.Avalonia/Platform/AvaloniaMessageBox.cs` | The themed message box from `MessageBoxPresenter`: buttons, Enter default, Esc button, close-box answer, icon glyph in its palette tone. |
| `Source/src/TabForge.Avalonia/Platform/AvaloniaFileDialogs.cs` | `IFileDialogs` (now in Core) on the StorageProvider; synchronous through a nested dispatcher frame; chosen paths pass `FilePathPolicy`. |
| `Source/src/TabForge.Avalonia/Platform/MixerFxButtons.cs` | The Mixer's drawn split FX button and amber MON button (twins of the WPF FxSplitButton and MonitorFxButton), drawn through `AvaloniaDrawContext`. |
| `Source/src/TabForge.Avalonia/Platform/ScorePreviewView.cs` | The main window's demo score: the shared Core score host and renderer drawn through `AvaloniaDrawContext`, as an editor surface (click, editor keys, digits, Ctrl+Z) through the Core `ScorePreviewEditor`. |
| `Source/src/TabForge.Avalonia/Platform/ScorePreviewView.Zoom.cs` | Partial of `ScorePreviewView`: the zoom factor, zoom steps, Fit width, first open at normal size and page coordinates. |
| `Source/src/TabForge.Avalonia/Platform/TimelineView.cs` | The arrangement timeline at rest, read-only: bar ruler, section strip, track rows with a block per occupied bar and the playhead line, from the Core timeline rules through `AvaloniaDrawContext`; the twin of the WPF `Views/TrackTimeline*.cs` without interaction, lanes, group headers or loop band; the master lane is drawn by MasterLaneStrip.cs, and section labels take light or dark ink by contrast. |
| `Source/src/TabForge.Avalonia/Platform/TimelineView.Drawing.cs`, `TimelineView.Settings.cs`, `TimelineView.Playhead.cs` | Partials of `TimelineView`: the body's drawing passes and caches; the display settings that redraw it; the playhead position and its x. |
| `Source/src/TabForge.Avalonia/Platform/ClipEditService.cs` | The pure clip edits the timeline commands share: the beat length for a tempo, moving a clip by seconds, moving it one lane up or down, and placing a copy on the wanted or first free lane (adding the lane rows each needs). Tests: `ClipEditServiceTests`, `MainWindowClipKeysTests`. |
| `Source/src/TabForge.Avalonia/Platform/TimelineHitTester.cs` | The composition of the arrangement's hit queries: a press's header cell first, else its section slot and then the row and bar with the grid and lane flags; the hover query (row, bar inside it, section strip). It delegates to the existing geometry of the view, the header and the clip painter. Tests: `TimelineHitTesterTests`, `TimelineInputTests`, `ArrangementClicks`. |
| `Source/src/TabForge.Avalonia/Platform/TimelineAudioClips.cs` | The arrangement's audio clips and lane bands: each clip's rectangle in its lane, the lane board and track tint, the selection outline, the WPF fade shading and the drop-lane highlight, and the clip hit test; drawn through `AvaloniaDrawContext` for `TimelineView`. Tests: `TimelineAudioClipTests`, `ClipEditingBatchFourTests`. |
| `Source/src/TabForge.Avalonia/Features/Recording/Presenter/LiveTakes.cs` | The takes being recorded for the live arrangement overlay (moved out of Platform): per armed track its start second, growing span, lane (recomputed over the span every frame), a bounded peak envelope (audio) or the notes heard so far (MIDI), and the rules that keep an audio take until its file lands while a MIDI take goes at Stop. Tests: `RecordingLiveTakeTests`. |
| `Source/src/TabForge.Avalonia/Features/Recording/View/TimelineLiveTakeLayer.cs` | The live recording overlay of the arrangement: one growing red box per take in its lane, the input envelope or notes, the "● REC" label and the per-take clip to the track rows, drawn on its own layer so a recording frame never repaints the timeline body (moved out of Platform). Tests: `RecordingLiveTakeTests`. |
| `Source/src/TabForge.Avalonia/Platform/KeyboardStripView.cs` | The keyboard falling-notes view's key strip: white and black keys at the Core `KeyboardStripGeometry`, palette keys, through `AvaloniaDrawContext`; the geometry is cached per size and range. Hosted in the Keyboard mode pop-out's KeysHost. |
| `Source/src/TabForge.Avalonia/Platform/InstrumentPanelView.cs` | The instrument panel (fretboard, keyboard, drum key map) through `AvaloniaDrawContext` with the score cursor's notes lit; a click raises a note-picked event carrying an `InstrumentNotePick` (no audio). Layouts and hit tests are the Core `FretboardGeometryRules`, `KeyboardGeometryRules` and `PercussionKeyMapRules`; the WPF panel's strum arrows are not drawn, while the scale highlights (shaded, circles or rings) and the fretboard's string and fret numbers and colour legend are. `InstrumentPanelStrip.cs` is the instrument pane: the panel (the kind follows the track), the Scales button under the legend and the close X; no title tab. |
| `Source/src/TabForge.Avalonia/Platform/InstrumentPanelView.Playback.cs`, `InstrumentPanelView.Labels.cs`, `InstrumentPanelView.Layouts.cs` | Partial files of `InstrumentPanelView`: the playing notes, the note and fret labels, and the keyboard and drum key-map layouts. |
| `Source/src/TabForge.Avalonia/Platform/UiTasks.cs` | `Forget(task, what, report)`: observes a task a UI command starts and does not await; a failure goes to the status notice (standard error without one). Test: `UiTasksTests`. |
| `Source/src/TabForge.Avalonia/Platform/MasterLaneStrip.cs` | The master lane: a thin line per track, filled over the bars the track plays, from MasterLaneRules. |
| `Source/src/TabForge.Avalonia/Platform/Controls/TrackPillButton.cs`, `Source/src/TabForge.Avalonia/Platform/Controls/FlatToolButton.cs` | The track capsule of a header strip (a track-colour dot and the name, in the Core "TrackPill" look and its idle style) and the flat tool button (transparent at rest, soft grey hover with an accent outline) that the compact strip's caption and close X use. Test: `CompactTrackStripTests`. |
| `Source/src/TabForge.Avalonia/Platform/Controls/ToolbarMenuRows.cs`, `Source/src/TabForge.Avalonia/Platform/Controls/BandViewMenu.cs`, `Source/src/TabForge.Avalonia/Platform/Controls/HeaderModeCaption.cs` | The toolbar's toggles as menu rows (shared by the compact menu and the band menu), the Band view's layout menu (fretboard beside or above, colour frame, Reset view, then the Band view and Compact mode ticks), and the caption that names the header mode entered last. Test: `CompactBandHeaderTests`. |
| `Source/src/TabForge.Avalonia/Platform/Controls/TextLinkButton.cs` | The look of a text link button (transparent at rest, the soft hover shade), shared by the status bar's audio interface button and the Settings changes link. |
| `Source/src/TabForge.Avalonia/Platform/BandView.cs`, `Source/src/TabForge.Avalonia/Platform/BandTrackPanel.cs`, `Source/src/TabForge.Avalonia/Platform/BandFretboardIcon.cs`, `Source/src/TabForge.Avalonia/Platform/BandSongCards.cs`, `Source/src/TabForge.Avalonia/Platform/BandPlayheadFollow.cs`, `Source/src/TabForge.Avalonia/Views/BandWindow.cs` | The Band view: one card per shown track (multi-select from the header strip, stacked in one scroll viewer), each with a track-colour border, a header with its name and a fretboard toggle, its fretboard (first shown card on by default), and a tab-only staff at 100% showing a window of `ShownSystems` systems; the cards share one bar layout so bar N lines up across them (`ShareBarWidths`); each open song keeps its cards and fretboards (`BandSongCards`); while playing, every card's window slides to the playing bar's system unless Follow is off (`BandPlayheadFollow`). Tests: `BandCardTests`, `BandViewTests`, `BandCompactModesTests`, `BandPlayheadFollowTests`. |
| `Source/src/TabForge.Avalonia/Platform/AvaloniaEditorKeys.cs` | Avalonia `Key` to Core `EditorKey`, the twin of the app's `WpfEditorKeys`. |
| `Source/src/TabForge.Avalonia/Platform/AvaloniaMonitorWorkAreas.cs` | `IMonitorWorkAreas` from the screens' working areas in DIPs (most overlap, then nearest); no screens returns the bounds unchanged. |
| `Source/src/TabForge.Avalonia/Platform/AvaloniaWindowChrome.cs` | `IWindowChrome` over a plain Avalonia window: move and resize drags (the title row passes the press first), minimise, maximise toggle, close and the state event. The Win32 frame hit test is separate. |
| `Source/src/TabForge.Avalonia/Platform/UiTiming.cs` | The one named source of the app's UI durations (milliseconds): settings save and preview, update check, autosave, menu open/close, frame timers, dock layout debounce and tab motion; purposes that share a value keep separate entries. Test: `UiTimingTests`. |
| `Source/src/TabForge.Avalonia/Platform/SettingsDefaults.cs` | The fallback settings of a reader with no store: a fresh `AppSettings` per call (never shared, since a caller may change it). Test: `SettingsDefaultsTests`. |

`KeyboardStripView.cs` is the keyboard falling-notes view; it draws through `KeyboardNotesPainter.cs` (bars, marks) and `KeyboardChromePainter.cs` (panel, strip, lit keys, legend, score, progress, grade), with the colours of `KeyboardInk.cs`.

- `AvaloniaScrollBarStyles`: the WPF 12 DIP scroll bar template (always visible, rounded thumb in ScrollThumbBrush).
- `InstrumentBadgeView`: one catalogue instrument badge drawn through IDrawContext from Core `InstrumentBadge`.
